# 加盟者・各社用の「型」（吹き出し予約ページ＋予約後の案内係チャット）

例え話：本番の `welcome/` は「ありがとうエアコン専用の制服」。この型は、寸法表（会社ごとの設定1枚）を入れると、その会社のサイズの制服が出てくるミシンです。

## 加盟者がすること
記入票（プロジェクトの `arigatou-system/kata/加盟者用_記入票.md`）の質問に答えるだけ。プロンプトも GitHub も触らない。

## 本部（Claude）がすること
1. `kata/hinagata.json` を `kata/companies/c0XX.json`（会社番号）に写し、記入票の答えを入れる。
2. `node kata/build.mjs c0XX` → `shop/c0XX/test/`（試し用ページ）ができる。止まったら、出た文の通りに設定を直す。
3. 試し用ページ `https://miumiumiu4.github.io/arigatou-booking/shop/c0XX/test/` をその会社に見てもらう。予約は本番の帳簿に入らない（`test_booking_url` が空なら画面だけ）。
4. HAPPY の判断と三浦さんの「出してよい」の後で、`booking_url`（その会社の帳簿の受け口）を入れて `honban: true` → `shop/c0XX/` が本番ページになる。

## 差し替える所・共通の所（設計書 3-2）
| 差し替える（設定1枚） | 全社共通（welcome/ から自動で写る） |
|---|---|
| 屋号・ロゴ・電話・LINE・会社名 | キャラ4人と口調、会話の流れ、画面の作り |
| 料金表・その他のお掃除・指名料 | 掃除の一般的な説明の答え（片づけ・電源と水道・頻度 など） |
| 対応エリア・希望時間帯・支払い方法 | 解決しない時に人へつなぐ決まり |
| 予約の届け先（その会社の帳簿） | 県の言葉（ブルース） |
| FAQ の金額・約束・支払い・保証の答え（出典つき） | |
| クーポン欄・紹介リンクの有無と文 | |

## 決まり（build.mjs が止めて守らせる）
- その会社の出典が無い答えは出さない。`faq` に書かない問は、チャットが答えずに人へつなぐ。`faq` には `faq_source` が必須。
- 料金表から自動で作る答えは C03・C07・F04・F05 だけ（その会社の料金表が出典）。
- 「追加料金なし」は例外と一緒に書く（C02）。「お疲れ様」「無理」は使わない。
- ありがとうエアコンの値（屋号・電話・LINE・予約の受け口・広告タグ）が1つでも残ったら止まる。
- 本番と試しの届け先は同じにできない。本番ページは `honban: true` と `booking_url` がそろった会社だけ。
- 外国の言葉の束（ブルースの英語など）は、ありがとうエアコンの数字ごと訳した物なので各社では出さない。県の言葉は、差し替える問には使わず共通の問だけに使う。
- 作業時間の計算（予約の台数から○分〜○分）はありがとうエアコンの目安なので、各社では使わない。
- ありがとうエアコンの Google 広告タグは各社のページでは読み込まない。

## welcome/ を直したとき
`node kata/build.mjs` で全社を作り直す。CI（kata の型と各社ページが合っているか）が作り直し忘れで赤になる。
本番の `welcome/` は、この型のために書き換えない。

## 確かめ方
- `node kata/build.mjs --check`
- `NODE_PATH=$(npm root -g) node kata/test/e2e.cjs`（C999 の試し用ページを通しで。どこにも送らない）

## まだ足りない所
- チャットの「LINE か電話で」という台詞は、LINE の無い会社でもそのまま出る（連絡先の箱は電話だけになる）。
- 予約の受け口（各社の帳簿）を置く手順は、単体版（HUB_MODE=none）の設置手順に入れる。
